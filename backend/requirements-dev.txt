# ---- why the CVE floors (every service carries them) ----------------------------
# starlette: GHSA-7f5h-v6xp-fcq8 (Range header DoS) + GHSA-2c2j-9gv5-cj73 (upload event-loop
# block) + PYSEC-2026-161 + CVE-2026-54283 (form limits ignored for
# application/x-www-form-urlencoded, DoS). fastapi<0.133.0 capped starlette<0.51.0, so the fix
# needed fastapi>=0.133.0; 0.136.1 is used.
# urllib3: GHSA-qccp-gfcp-xxvc + GHSA-mf9v-mfxr-j63j (redirect header leak, Brotli
# decompression bomb), CVE-2026-97687 (HTTPS proxy TLS config override), CVE-2026-97689 (chunk
# parser memory DoS). Pulled in by the openai / anthropic / google-auth SDKs.
# requests: GHSA-gc5v-m9x4-r6x2 (predictable temp file in extract_zipped_paths). Not exploitable
# via current code paths; pinned for defence in depth. Pulled in by google-auth[requests].
# python-dotenv: GHSA-mf9w-mj56-hr94 (symlink follow in set_key/unset_key). Not called at
# runtime; only affects local .env writes (auth.seed).
#
# ---- disputed / no-fix advisories ----------------------------------------------
# PyJWT PYSEC-2025-183: "weak encryption", DISPUTED by the PyJWT maintainers. The finding is
# that callers may supply short HMAC keys; the library doesn't enforce a minimum length. Not
# applicable: tokens are RS256 with a 2048-bit RSA key pair. No fixed version exists; pip-audit
# ignores it (scripts/audit-backend-services.sh).
