# API Overview

Nine backend services under `backend/` serve the API. Public routes are under `/api/v1`, except shared's `/api/health`. The tables below give paths without the `/api/v1` prefix.

| For | Read |
|---|---|
| Routes, limits and errors, current | This file |
| Exact request and response shapes | The OpenAPI specs, `backend/openapi/<service>.json` (generated, checked in CI) |
| Why each endpoint works the way it does | [auth-users-split-api.md](auth-users-split-api.md): the historical design record from the service split. Its "Today" notes describe the removed `backend/app/`. |

## How it fits together

| Topic | How it works |
|---|---|
| **Specs** | Each HTTP service commits its OpenAPI spec, `backend/openapi/<service>.json`, written by `python backend/tools/export-openapi.py --service <service>`. CI fails if a committed spec differs from the code, and Spectral lints them (`.spectral.yaml`). |
| **Typed clients** | `frontend/src/api/generated` and `frontend-app/src/api/generated` are generated from the specs by `node scripts/sync-api-clients.mjs`. |
| **Routing** | [`shared/service-routes.json`](../shared/service-routes.json) maps each public path to its service, in priority order. It is the single source for the AWS ALB's listener rules (`infra-live-backend/terraform/alb.tf`) and the local nginx gateway (`local/gateway/nginx.conf`, generated by `node scripts/sync-gateway.mjs`). Connect (`/api/v1/children/*/connect*`) is listed but not built, so it isn't routed. |
| **Local** | The API is at `http://localhost:8088/api/v1/...`. `GET /gateway/health` is the gateway's own check. |
| **Internal APIs** | Each service also runs an internal app on port 8001 (`/internal/...`), which the ALB and the gateway never route. Service-to-service calls are signed with per-service keys. |
| **Auth** | auth issues RS256 tokens, and every other service verifies them with the public keys. A token comes from the `access_token` cookie or `Authorization: Bearer`. |
| **Rate limits** | Per route, counted in Valkey (`backend/common/limiter.py`). The tables give each route's limit, per user unless marked per IP. |
| **Health** | Every service serves `GET /health` on its public port (8000 in the container) for the load balancer. It isn't routed outside. |

## Rules for every route

| Rule | Detail |
|---|---|
| **Error shape** | FastAPI's `{"detail": …}`. Where the apps must tell errors apart, `detail` is `{"code": "…", "msg": "…"}`; the tables below give the `code`. |
| **Body size** | A request body over 1 MiB is refused with `413 body_too_large` before it is read (shared's speech-to-text: 10.5 MiB). This applies whether `Content-Length` says so or a chunked body gets there. |
| **Child id** | A child's `{id}` in any path is a uuid4; anything else is `422`. So it can't add a query or a segment to the internal calls it's passed on to. |

## Circle unlock order

Each circle opens once the one before it is done. Until then its routes return `403 circle_locked`, after asking the owner service first.

```
profile complete ─► onboarding ─► discover ─► grow ─► transform ─► release ─► connect
 (children)          answers       reveal      an area   Day-90       something
                     saved         passed      completed  event set    watched
```

The same access rules hold in every circle:

| Case | Response |
|---|---|
| Someone else's child, a deleted child or an unknown child | `404 child_not_found` |
| The previous circle isn't done | `403 circle_locked` |
| The owner service can't be asked | `503 <owner>_unavailable` with `Retry-After` (e.g. `children_unavailable`, `onboarding_unavailable`) |
| An admin reading | Passes the owner's `?location=`, and the read is audited |

## Generation jobs (discover, grow, transform, release)

The client never sends a prompt: the server builds it from its own data and local copies.

| Response | Meaning |
|---|---|
| `202 {job_id, status}` | Job started |
| `200` | A job of the same kind is already `pending` or `processing` for that child (and area), and it is returned instead of starting another |
| `409 already_generated` | The result is made only once (discover, grow's question sets); checked again when the job is stored |
| `429 llm_limit` | Past the hourly LLM limit |
| `GET …/generation/{job_id}` | Polls the job (`kind`, `status`, `error`): 300/min, because it is polled while the job runs. Another child's job is `404 job_not_found`. |

| Rule | Detail |
|---|---|
| **Start limits** | 10 starts a minute per user, plus an hourly LLM limit per user shared by every circle (`LLM_HOURLY_LIMIT`, default 200, counted in Valkey). A start that finds the job already running gives its slot back, so two clicks at once count once. |
| **Job status** | `pending` → `processing` → `completed` or `failed`. When `completed`, the result is already stored, so the client reloads the circle's `GET`. |
| **Failures** | The worker retries the LLM call with backoff. A job that still fails, crashed, or stalled on every attempt ends `failed` with a short `error`, and the client may start it again. |
| **Superseded** | When what a running job builds from changes (transform: a new `ask` or Day-90 event, `clear_track_steps`, an age or gender change, an updated growth area), the job ends `failed` with `superseded: its inputs changed` in the same transaction, and its result is never stored. Start it again for the new inputs. |
| **Long text** | A text longer than its schema allows is cut at a word with "…" rather than failing the job. |

## auth

Errors the apps tell apart carry `detail.code`.

| Method | Path | Limit | What it does | Errors |
|---|---|---|---|---|
| POST | `/auth/register` | 5/min per IP | Allow-listed emails only. `first_name` (required), `middle_name`, `last_name`, `country_code`, optional address lines; no `full_name`. Runs the registration saga: reserve the email's HMAC key, save credentials, create the users profile, activate. `201` with tokens and cookies. | `403 registration_closed`, `409 email_taken`, `503 registration_unavailable` (users unreachable; retry) |
| POST | `/auth/login` | 10/min per IP | Signs in. The lock is revealed only with the right password. 5 failures in 15 minutes for one email from one IP block that pair. | `401 invalid_credentials` (any wrong email or password), `403 account_locked`, `429 too_many_attempts` |
| POST | `/auth/google` | 5/min per IP | Signs in an existing account whatever its provider, or creates one (allow-list applies). | `422 country_code_required` |
| POST | `/auth/refresh` | 20/min | Rotates the refresh token within its family. A rotated token reused within 30 s also gets a pair; later, it revokes the family and logs the account out everywhere. Every refusal clears both cookies. | `401 session_revoked` |
| POST | `/auth/logout` | 20/min | `204` always, unless the tokens belong to different users. | |
| POST | `/auth/logout-all` | 3/min | `204`: ends every session and every older access token. | |
| GET | `/auth/me` | 60/min | `id`, `email`, `role`, `auth_provider`, `location`, `created_at`. Names are in the users service. | |
| DELETE | `/auth/account` | 3/min | Body `{"confirm_email"}`. `202 {"status": "deleting"}`: signed out everywhere at once, and the data is deleted as each service confirms (`DELETION_PARTICIPANTS`: the seven services that hold user data). The email is free again when the saga finishes. | `400 confirmation_mismatch`, `409 account_changed` (role or lock changed meanwhile) |

**Admin routes** (each needs its permission, audited, 60/min):

| Method | Path | What it does |
|---|---|---|
| GET | `/auth/accounts` | Lists accounts. Filters `role`, `locked`; `skip` / `limit`. |
| POST | `/auth/accounts/search` | Finds an account by email (in the body). |
| POST | `/auth/accounts/{id}/lock` | Locks the account and signs it out everywhere. |
| POST | `/auth/accounts/{id}/unlock` | Unlocks it; the old tokens stay invalid. |
| PATCH | `/auth/accounts/{id}/role` | Changes the role and signs the account out everywhere. |
| GET | `/auth/allowed-emails` | Lists the allow-list. |
| POST | `/auth/allowed-emails/search` | Finds an allow-list entry. |
| POST | `/auth/allowed-emails` | Adds an email. |
| DELETE | `/auth/allowed-emails/{key}` | Removes an entry by its HMAC key, never an email. |

| Rule (lock, unlock, role) | Response |
|---|---|
| Needs the account's `?location=` | |
| `{id}` must be the account's user id, a uuid4; anything else is refused before it reaches the database or a log | `422` |
| Never the last active admin | `409 last_admin` |
| Never an account being deleted | `409 account_deleting` |

| Internal | Purpose |
|---|---|
| `GET /internal/auth/users/{user_id}/email?location=` | A user's email, for a service that must contact them. No service is allowed yet (`403`), and every read is audited. |
| `GET /internal/authz/{user_id}` (port 8001) | The account's authz entry, for the other services' cache misses (every service that verifies tokens calls it). It refills Valkey. |

| Other | Detail |
|---|---|
| Tokens | Access tokens carry `role` and `iat_ms`; refresh tokens carry `family_id`. Every sign-in writes the account's `authz:{user_id}` entry to Valkey through the versioned write. |
| Local seed | `docker compose exec auth python -m auth.seed` adds `LOCAL_ALLOWED_EMAIL` (from `.env`) to the local allow-list. |
| Worker | Keeps each region's cached authz entries current from a change stream on `auth.auth`, and reaps registrations abandoned for 15 minutes. |

| Rule | Detail |
|---|---|
| Photo keys | S3 keys under the child's `…/ninety-day-plan/`, uploaded, an allowed image, at most 5 MB. |
